# All configuration options

Generated from `autoclip/app/fields.py`; do not edit by hand.

## Videos

What to cut and where the result goes

| Path | Kind | Vision | Details |
|---|---|---|---|
| `input` | `lines` | normal | **What:** The videos to work on: full paths, a glob such as `talks/*.mp4`, or one path per line. **Why:** The batch is the unit of work: every video gets its own clips, and one broken file never stops the others. **When:** Fill this in first - it is the only option without a useful default. |
| `output_dir` | `dir` | normal | **What:** Where the clips are written: `<output>/short/<video>/` and `<output>/long/<video>/`. **Why:** Keeps the results of a run together and away from the source footage. **When:** Set it once per project; the work files (database, transcript cache) and the logs follow it. |
| `compute.device` | `choice` | normal | **What:** Where the heavy work runs: `cpu` never touches the GPU, `gpu` insists on it, `auto` uses it when there is a usable one. **Why:** `cpu` is the safe choice on a laptop (no heat, no driver trouble); a GPU is several times faster. **When:** Use `cpu` on shared or battery-powered machines, `auto` everywhere else. Choices: `auto, cpu, gpu`. |

## Download

What to download from a URL, and from which platforms

| Path | Kind | Vision | Details |
|---|---|---|---|
| `download.quality` | `str` | normal | **What:** The short side of the video to download: a number such as `1080`, or `best` / `worst`. **Why:** The clips are rendered at the `video.short_side` of their kind, so downloading 4K costs time and disk for pixels that are thrown away. **When:** Lower it on a slow connection, raise it when the originals should stay at full size. |
| `download.fps` | `float` | normal | **What:** The frame rate to prefer (`24`, `30`, `50`, `60`); empty takes whatever the platform offers. **Why:** Matching the rate of the source keeps motion smooth; a lower rate downloads faster. **When:** Empty normally; set it when the platform offers several variants and you need one of them. |
| `download.prefer` | `choice` | normal | **What:** What to do when there is no stream at exactly the requested quality and frame rate: take the closest one, never go above it or never go below it. **Why:** A hard cap saves bandwidth and disk; `at_least` avoids a soft result on a large screen. **When:** Leave it at `closest` unless a quota or a minimum matters. Choices: `closest, at_most, at_least`. |
| `download.codec` | `choice` | normal | **What:** The codec to prefer: `auto` ranks h264 first, then vp9, av1 and h265; a name restricts the choice to it. **Why:** h264 plays everywhere and edits fast; av1 and vp9 are smaller but slower to decode. **When:** `auto` normally, `h264` when the clips have to play on old devices. Choices: `auto, h264, vp9, av1, h265`. |
| `download.container` | `choice` | normal | **What:** The file extension to prefer: `auto` keeps the format's own container, `mkv` accepts anything. **Why:** mp4 is the friendliest for players and editors; mkv holds codecs mp4 cannot. **When:** `auto` unless a tool downstream insists on a container. Choices: `auto, mp4, mkv, webm`. |
| `download.audio_quality` | `choice` | advanced | **What:** Whether to take the best or the worst audio track the platform offers. **Why:** The clips re-encode the audio anyway, so the worst track is smaller and often indistinguishable. **When:** `best` for the archive, `worst` to save bandwidth on a long playlist. Choices: `best, worst`. |
| `download.audio_language` | `str` | advanced | **What:** The language of the audio track, for example `en`; empty keeps the video's original language. **Why:** A video with several audio tracks may otherwise give you a dub you do not want. **When:** Only for videos with more than one track. |
| `download.original_dir` | `dir` | normal | **What:** Where the downloaded originals are kept; empty uses `<output>/.work/downloads/`, which later runs reuse. **Why:** A dedicated folder is easier to back up or to move to another disk. **When:** Empty normally; set it when the originals should outlive the output folder. |
| `download.metadata.info_json` | `bool` | normal | **What:** Write `<title> [<id>].info.json` next to every original. **Why:** The file holds the title, channel, upload date and every format the platform offered. **When:** Keep it on - it documents where a clip came from. |
| `download.metadata.thumbnail` | `bool` | normal | **What:** Write the platform's cover image next to the original. **Why:** A ready-made cover can be reused in an edit or as the still of the clip. **When:** On when the thumbnails are part of the material. |
| `download.metadata.description` | `bool` | normal | **What:** Write the video description to a text file next to the original. **Why:** The description often carries chapters, credits and links that the transcript lacks. **When:** On for research, or when the description feeds a publish. |
| `download.subtitles.enabled` | `bool` | normal | **What:** Download the subtitles the platform offers, as SRT files next to the original. **Why:** The platform's own subtitles avoid a Whisper pass and are often better on names and music. **When:** On when the videos have subtitles and the transcription should be quick. |
| `download.subtitles.languages` | `csv` | normal | **What:** The language codes to ask for, in order of preference, for example `en, ar`. **Why:** Only these languages are requested, and the first usable one may become the transcript. **When:** List every language you can work with. |
| `download.subtitles.use_as_transcript` | `choice` | normal | **What:** Whether a downloaded subtitle may replace the transcription: `never` keeps it as a file only, `manual` lets human-made subtitles replace Whisper, `always` lets automatic ones replace it too. **Why:** Platform subtitles are free and fast, but automatic ones can be worse than Whisper. **When:** `manual` is the safe choice when the platform has real subtitles; be careful with `always`. Choices: `never, manual, always`. |
| `download.playlist` | `choice` | normal | **What:** What to do with a URL that points at a playlist: `single` downloads the one video, `all` every entry. **Why:** A video URL often carries a playlist id, and `single` stops it from downloading a whole channel by accident. **When:** `single` normally, `all` when the list is the material. Choices: `single, all`. |
| `download.max_videos` | `int` | normal | **What:** How many entries `all` downloads at most. **Why:** A channel can hold thousands of videos; the cap keeps a typo from filling the disk. **When:** Raise it for a real archive run. |
| `download.time_range` | `str` | normal | **What:** Download only a part of the video, `MM:SS-MM:SS` or `HH:MM:SS-HH:MM:SS`; empty downloads all of it. **Why:** A long stream often has only a short interesting section, and the transfer is the slow part. **When:** Set it when you know the section; the subtitle timings are shifted to match. |
| `download.cache` | `bool` | normal | **What:** Whether the originals already downloaded here for the same URL and settings are reused with no network request. **Why:** Re-downloading identical videos is slow and burns rate limits; recycling the cache keeps the run offline-friendly. **When:** Leave it on. Turn it off to force a fresh pull (then turn it back on). |
| `download.cookies.from_browser` | `str` | advanced | **What:** Read the cookies of a signed-in browser (`chrome`, `firefox`, `edge`, `safari`, ...) to download private or age-restricted videos. **Why:** Some videos need the session that already exists in the browser. **When:** Only when a download fails asking to sign in; leave it empty otherwise. |
| `download.cookies.file` | `path` | advanced | **What:** A Netscape-format `cookies.txt`, as an alternative to reading a browser. **Why:** It works without the browser installed and can be stored apart from the browser profile. **When:** When the browser is on another machine; set only one of the two sources. |
| `download.network.proxy` | `str` | advanced | **What:** The proxy every request goes through: `http://host:port` or `socks5://host:port`. **Why:** Some networks only reach the internet through a proxy. **When:** Empty normally; set it when downloading fails behind a corporate network. |
| `download.network.rate_limit_mbps` | `float` | advanced | **What:** The maximum download rate in Mbit/s; empty means no limit. **Why:** Keeps a large playlist from saturating the connection. **When:** Set it when a download runs next to a video call. |
| `download.network.retries` | `int` | advanced | **What:** How often a failed request is tried again. **Why:** A flaky connection recovers without losing the whole entry. **When:** Raise it on a bad line, lower it to fail fast. |
| `download.network.socket_timeout` | `float` | advanced | **What:** How long to wait for a silent connection before giving up, in seconds. **Why:** A hung connection would otherwise block the whole batch. **When:** Raise it on a very slow connection. |
| `download.network.sleep_between_seconds` | `float` | advanced | **What:** How long to wait between two playlist entries, in seconds. **Why:** A polite pause makes the platform less likely to rate-limit the batch. **When:** A second or two for long playlists. |
| `download.js_runtime.name` | `choice` | advanced | **What:** The runtime yt-dlp uses to solve YouTube's signature challenges; `auto` finds one on the PATH. **Why:** YouTube serves some formats only to clients that can run its JavaScript. **When:** Leave `auto` when deno, node, bun or quickjs is installed; name one when several are. Choices: `auto, deno, node, bun, quickjs`. |
| `download.js_runtime.path` | `path` | advanced | **What:** The binary of the named runtime, when it is not on the PATH. **Why:** A runtime in a non-standard place can still be used. **When:** Only with a named runtime - `auto` ignores the path. |
| `download.js_runtime.remote_components` | `choice` | advanced | **What:** Whether yt-dlp may download the EJS challenge solver at run time. **Why:** The solver keeps YouTube working when the bundled one is out of date, but it is code fetched from the internet. **When:** `none` unless YouTube starts failing without it. Choices: `none, ejs`. |
| `download.platforms.allow` | `csv` | normal | **What:** The platforms that may be downloaded: platform names (`youtube`, `vimeo`, ...) and the groups `@popular`, `@social`, `@video`, `@all`, plus your own. **Why:** A URL is only downloaded when it is on this list - everything else is refused before a request is made. **When:** Start with `@popular` and add the platforms you use. |
| `download.platforms.deny` | `csv` | normal | **What:** Platforms that are never downloaded, even when an allow entry covers them. **Why:** Deny wins over allow, so a broad group can stay while one platform is excluded. **When:** Add a platform that you do not want to support. |
| `download.platforms.groups` | `json` | advanced | **What:** Named groups of platform names, as a JSON object: `{"@news": ["youtube", "vimeo"]}`. **Why:** A group is allowed and overridden once and then reused everywhere a platform name is accepted. **When:** When the allow list repeats the same set of platforms. |
| `download.platforms.settings` | `json` | advanced | **What:** Overrides for one platform or one of your groups, as a JSON object using the options above: `{"youtube": {"quality": 720}}`. **Why:** A short-video platform often needs a different quality or codec from the rest. **When:** When one platform repeatedly needs other settings. |
| `download.platforms.group_by_platform` | `bool` | advanced | **What:** Put the downloaded originals in `<downloads>/<platform>/` instead of one flat folder. **Why:** Keeps a mixed batch tidy and makes one platform's files easy to find. **When:** On when the batch draws from many platforms. |

## Clips

Which moments become clips, and how long they are

| Path | Kind | Vision | Details |
|---|---|---|---|
| `clips.mode` | `choice` | normal | **What:** What to produce: `highlights` picks the best moments, `ranges` cuts the exact ranges you list, `split` cuts the video into equal parts. **Why:** `ranges` gives full control when you already know the timestamps, `split` prepares footage for further editing. **When:** Leave it at `highlights` unless you want to mark the cuts yourself. Choices: `highlights, ranges, split`. |
| `clips.kinds` | `csv` | normal | **What:** Which clip lengths to produce: `short` (vertical, for TikTok/Reels/Shorts) and/or `long` (horizontal, for YouTube). **Why:** The kinds are rendered with different shapes and different length rules, so each one needs its own settings. **When:** Pick `short` for social posts, `long` for a compilation video, both for a full package. |
| `clips.scenes` | `csv` | normal | **What:** The kinds of moment to look for: `best`, `attractive`, `exciting`, `funny`, `sad`, `emotional`, `inspiring`, `calm`, `educational`, `controversial` - or `all`. **Why:** Each type has its own scoring, so `funny` finds the jokes and `educational` the explanations. **When:** Use `all` for a wide selection, a single type when you only want that mood. |
| `clips.short.count` | `int` | normal | **What:** How many short clips are produced for each scene type. **Why:** More clips mean more chances that one of them hits; they compete for the same moments, so a later type may get fewer. **When:** Raise it for a big batch of social posts, lower it to keep only the strongest moments. |
| `clips.short.min_seconds` | `float` | normal | **What:** The shortest a short clip may be; the pause removal gives cuts back rather than going below it. **Why:** Very short clips often feel abrupt, and platforms prefer a few seconds of context. **When:** Raise it when the clips feel choppy, lower it for very punchy edits. |
| `clips.short.target_seconds` | `float` | normal | **What:** The length the clips tend to get: candidates near it get a small score bonus, but it stays a preference, not a limit. **Why:** The scene type still decides the content - the target only nudges the length towards what usually works. **When:** Leave it empty to take whatever length the content offers, set it when you know the platform's sweet spot. |
| `clips.short.max_seconds` | `float` | normal | **What:** The longest a short clip may be; the padding around the cut cannot push it over. **Why:** Long clips lose viewers on the first seconds, and the platform's own limits are short. **When:** Keep it at or below the platform limit (60 s for Reels and Shorts). |
| `clips.short.aspect` | `str` | normal | **What:** The shape of the short clips: `9:16`, `1:1`, `4:5`, `16:9` or `original`. **Why:** A vertical frame uses the screen of a phone best; `original` keeps the source shape. **When:** Use `9:16` for TikTok, Reels and Shorts, `1:1` for feed posts. |
| `clips.short.ranges` | `lines` | normal | **What:** Exact ranges to cut in `ranges` mode, one `HH:MM:SS-HH:MM:SS` per line. **Why:** You decide where the clips start and end instead of the automatic finder. **When:** Only in `ranges` mode - the ranges belong to the `short` kind. |
| `clips.long.count` | `int` | normal | **What:** How many long clips are produced for each scene type. **Why:** Long clips cost real time to render, so fewer of them is usually the right choice. **When:** One per scene type is enough for a compilation; more only when the material is rich. |
| `clips.long.min_seconds` | `float` | normal | **What:** The shortest a long clip may be. **Why:** A long clip that is not really long wastes the format. **When:** Keep it well above the short minimum (three minutes and more is the usual range). |
| `clips.long.target_seconds` | `float` | normal | **What:** The length the long clips tend to get - a preference, not a limit. **Why:** Long clips work best when they hold a complete thought, and the bonus keeps them around a predictable size. **When:** Set it to the length your platform and your audience expect. |
| `clips.long.max_seconds` | `float` | normal | **What:** The longest a long clip may be. **Why:** Keeps a single clip from running past the attention span - and the render time with it. **When:** Ten minutes is a good ceiling for a compilation piece. |
| `clips.long.aspect` | `str` | normal | **What:** The shape of the long clips: `16:9`, `9:16`, `1:1`, `4:5` or `original`. **Why:** A long clip is usually watched on a big screen, so it keeps the horizontal shape. **When:** Use `16:9` for YouTube, `9:16` when the long clip is meant for a phone. |
| `clips.long.ranges` | `lines` | normal | **What:** Exact ranges to cut in `ranges` mode, one `HH:MM:SS-HH:MM:SS` per line. **Why:** You decide where the clips start and end instead of the automatic finder. **When:** Only in `ranges` mode - the ranges belong to the `long` kind. |
| `clips.keywords` | `csv` | advanced | **What:** Extra words or phrases that boost a moment, in any language. **Why:** The built-in word lists are English; your own words make the finder work in your language or on your topic. **When:** When the automatic scoring misses what you mean by a good moment (brand names, technical terms, a catch phrase). |
| `clips.lexicon_file` | `path` | advanced | **What:** A JSON file with your own word lists per feature, for example `{"funny": ["my catch phrase"]}`. **Why:** Extends the built-in English lists with your own vocabulary, feature by feature. **When:** When `keywords` is not enough because you want many words per feature. |
| `clips.skip_intro_seconds` | `float` | normal | **What:** Seconds at the start of the video that are never used. **Why:** Introductions, greetings and housekeeping are rarely the best moment of a talk. **When:** When the video opens with a long preamble. |
| `clips.snap_to_cuts` | `bool` | normal | **What:** Move the cut points to the nearest shot change instead of cutting in the middle of a shot. **Why:** A cut that lands on a camera change looks intentional and is less jarring. **When:** For edited or multi-camera footage; it needs the optional `scenedetect` package. |
| `clips.pad_start` | `float` | advanced | **What:** Extra seconds kept before the first word of a clip. **Why:** A little breathing room stops the clip from starting too abruptly. **When:** Raise it if the first word is cut off; lower it for a punchy start. |
| `clips.pad_end` | `float` | advanced | **What:** Extra seconds kept after the last word of a clip. **Why:** The ending should not fall on the last syllable. **When:** Raise it if the last word is cut off; lower it for a punchy ending. |
| `clips.split_seconds` | `float` | normal | **What:** The length of the parts in `split` mode. **Why:** Fixed-length parts are easy to upload, archive or edit further. **When:** Only in `split` mode. |

## Transcript

How the spoken text is obtained

| Path | Kind | Vision | Details |
|---|---|---|---|
| `transcript.mode` | `choice` | normal | **What:** Where the text comes from: `auto` uses your subtitle file when there is one and transcribes otherwise, `whisper` always transcribes, `file` only reads your file, `off` uses no text at all. **Why:** Transcription is the slowest part of a run, so an existing subtitle file makes it instant. **When:** Use `file` when you already have subtitles, `off` when you only want an automatic cut. Choices: `auto, whisper, file, off`. |
| `transcript.file` | `path` | normal | **What:** Your subtitle file (.srt or .json); `{stem}` is replaced by the name of each video. **Why:** Skips the transcription and gives exact word timings. **When:** Whenever you have subtitles; with several videos the name must contain `{stem}`. |
| `transcript.cache` | `bool` | normal | **What:** Keep the transcript in the work folder and reuse it while the video, the model and the language do not change. **Why:** Re-running the selection then costs nothing instead of paying for the transcription again. **When:** Keep it on; turn it off only when you want every run to start from scratch. |
| `transcript.model` | `str` | normal | **What:** The speech model: `tiny`, `base`, `small`, `medium` or `large-v3` (multilingual, not the `.en` ones). **Why:** Bigger models understand accents, noise and rare words better, but need more time and memory. **When:** `large-v3` for the final result, `small` or `base` for a quick first look. |
| `transcript.model_dir` | `path` | normal | **What:** Folder where Whisper models are stored; empty uses the default HuggingFace cache. **Why:** Lets you point a run at a pre-downloaded model folder on an offline machine. **When:** Set it when models live outside the default cache. |
| `transcript.offline` | `bool` | normal | **What:** Fail instead of downloading a missing Whisper model. **Why:** Keeps an offline machine from hanging on a multi-gigabyte download. **When:** Turn it on for air-gapped runs. |
| `transcript.consent` | `choice` | normal | **What:** What to do when a Whisper model is not yet on the machine: `ask` prompts (a dialog in the app, a question on the terminal), `auto` downloads it without asking, `never` fails fast. **Why:** A download is several hundred megabytes, but running with a too-small model gives a worse transcript. **When:** Keep `ask` on a workstation, set `auto` for unattended or server runs, `never` for air-gapped machines. Choices: `ask, auto, never`. |
| `transcript.auto_downgrade` | `bool` | advanced | **What:** Fall back to a smaller model automatically when the machine has too little free memory. **Why:** Prevents the run from dying with an out-of-memory error on a small machine. **When:** Keep it on unless you need exactly one model and the fallback would surprise you. |
| `transcript.language` | `str` | normal | **What:** The language of the audio, for example `en`, `de` or `ar`; empty means detect it. **Why:** A known language is detected faster and more reliably than an automatic guess. **When:** When the detection picks the wrong language, or when you want to skip the detection. |
| `transcript.multilingual` | `bool` | advanced | **What:** Detect the language of every segment instead of the whole video. **Why:** Needed for videos that switch between languages. **When:** Only for mixed-language videos - it makes the transcription slower. |
| `transcript.device` | `choice` | advanced | **What:** Where the transcription runs: `cuda` on the GPU, `cpu` on the processor, `auto` on the GPU when there is one. **Why:** The GPU is several times faster, but it needs a matching CUDA setup. **When:** Leave it at `auto`; `compute.device = cpu` overrides it anyway. Choices: `auto, cpu, cuda`. |
| `transcript.beam_size` | `int` | advanced | **What:** How hard the model searches for the words: 1 is fastest, 5 is most accurate. **Why:** A larger beam size fixes more mistakes but takes proportionally longer. **When:** Use 1 for a quick test, 5 for the final render. |
| `transcript.word_timestamps` | `bool` | normal | **What:** Record the time of every single word. **Why:** Needed for the word-by-word caption highlight and for cutting filler words. **When:** Keep it on; turning it off saves a little time but loses the highlight. |
| `transcript.enhance.enabled` | `bool` | normal | **What:** Denoise the audio before it is transcribed. **Why:** A noisy recording makes the model write the wrong words - and the wrong language. **When:** On for a noisy recording, off for a clean one: denoising clean audio can only hurt it. |
| `transcript.enhance.backend` | `choice` | normal | **What:** Which denoiser to use: `sherpa` (a small ONNX model, needs the optional `sherpa-onnx` package) or `noisereduce` (spectral gating). **Why:** The two behave differently: the ONNX model removes the noise, the spectral gate only attenuates it. **When:** `sherpa` for speech recorded with a real microphone, `noisereduce` for hum and constant hiss. Choices: `sherpa, noisereduce`. |
| `transcript.enhance.model` | `choice` | advanced | **What:** Which denoiser model to use: `gtcrn` (fast, light) or one of the `dpdfnet` models (heavier, cleaner). **Why:** The bigger models remove more noise but cost more time per minute of audio. **When:** `gtcrn` is the good default; a `dpdfnet` model when the recording is really rough. Choices: `gtcrn, dpdfnet_baseline, dpdfnet2, dpdfnet4, dpdfnet8`. |
| `transcript.enhance.attenuation_limit_db` | `float` | advanced | **What:** How much the `dpdfnet` models may remove, in dB (0 = off, 100 = no limit). **Why:** Limits how much of the signal the denoiser may treat as noise. **When:** Raise it for very noisy recordings, lower it when the denoiser starts eating the quiet parts of words. |
| `transcript.enhance.denoise_strength` | `float` | advanced | **What:** How hard the `noisereduce` backend works, from 0 (off) to 1 (aggressive). **Why:** A stronger setting removes more noise but can leave a metallic sound. **When:** Start at the default and raise it only while the transcription is still wrong. |
| `transcript.enhance.snr_threshold_db` | `float` | normal | **What:** Only enhance the audio when its signal-to-noise ratio is below this value in dB; empty means always. **Why:** A clean recording (a screen capture with a good microphone, say) is only damaged by denoising. **When:** Keep it around 20 dB; lower it when you want the clean-up to run more often. |
| `transcript.enhance.num_threads` | `int` | advanced | **What:** How many threads the denoiser may use. **Why:** The denoiser is small, so more threads make it slower rather than faster. **When:** Leave it at 4 unless you know the machine better. |
| `transcript.enhance.model_dir` | `dir` | advanced | **What:** Where the denoiser model is kept; empty means the shared per-user cache (~/.cache/autoclip/models on Linux). **Why:** One copy per machine, shared by every output folder: a re-run no longer re-downloads it. **When:** Only when you want the model in a fixed place (an offline machine, for example). |

## Video

Shape, quality and background of the clips

| Path | Kind | Vision | Details |
|---|---|---|---|
| `video.short_side` | `int` | normal | **What:** The size of the short side of the output (1080 gives 1080x1920 for a vertical clip). **Why:** The resolution decides how sharp the clip is and how long it takes to render. **When:** 1080 for the final result, 720 or 540 for a quick look. |
| `video.upscale` | `bool` | normal | **What:** Whether a source smaller than `video.short_side` is blown up to the full canvas. **Why:** Enlarging cannot add detail: it only makes the file bigger and softer. It is off so the clip keeps the quality of the source. **When:** Turn it on only when the output must have an exact size (a platform that demands 1080p). |
| `video.fps` | `float` | normal | **What:** The frame rate of the output; empty keeps the rate of the source video. **Why:** A lower rate makes the file smaller and the render faster, at the price of motion. **When:** Leave it empty to keep the motion of the source; 30 is the usual choice when it has to be fixed. |
| `video.layout` | `choice` | normal | **What:** How the picture fills the frame: `fit` shows the whole frame on a background, `fill` crops it to the edges. **Why:** `fit` keeps everything visible but adds borders, `fill` looks native but may cut off parts. **When:** `fit` for talks and screen recordings, `fill` for footage that was shot for the format. Choices: `fit, fill`. |
| `video.background.type` | `choice` | normal | **What:** What fills the empty space around the picture: `blur` (a blurred copy of the frame), `color` (a flat colour) or `image` (your own picture). **Why:** The background frames the video and keeps the eye on the captions. **When:** `blur` is the safe default; `image` when the video is part of a series with its own look. Choices: `blur, color, image`. |
| `video.background.blur` | `float` | advanced | **What:** How strongly the background is blurred. **Why:** A stronger blur separates the picture from the background more clearly. **When:** Raise it when the background still competes with the foreground. |
| `video.background.dim` | `float` | advanced | **What:** How much the background is darkened, from 0 (as it is) to 1 (black). **Why:** Darkening the background makes the white captions easier to read. **When:** A little darkening (0.3-0.5) is enough for most footage. |
| `video.background.color` | `str` | normal | **What:** The colour of the flat background, for example `#101010`. **Why:** A flat colour is the cleanest background for captions. **When:** A near-black colour looks professional and keeps the captions readable. |
| `video.background.image` | `path` | normal | **What:** Your own picture, used as the background. **Why:** It gives a series of clips the same look, whatever the source video is. **When:** Only when the background should be part of your brand. |
| `video.fade_seconds` | `float` | normal | **What:** The length of the fade at the start and at the end of every clip. **Why:** A short fade softens the cut when the clip is played in a row. **When:** A fifth of a second is enough; use 0 for a hard cut. |
| `video.codec` | `choice` | normal | **What:** The video codec: `h264` plays everywhere, `h265` (HEVC) gives a smaller file at the same quality. **Why:** H.265 halves the size of a clip, but older players and some platforms do not accept it. **When:** `h265` for archive copies, `h264` for anything you upload. Choices: `h264, h265`. |
| `video.gpu` | `choice` | normal | **What:** Which hardware encoder to try: `auto` uses the first one that really works on this machine, `off` always uses the CPU. **Why:** A GPU encoder is much faster and leaves the processor free for the transcription. **When:** `auto` on a desktop with a supported GPU; `off` everywhere else, or when `compute.device` is `cpu`. Choices: `auto, off, nvenc, videotoolbox, qsv, amf`. |
| `video.crf` | `int` | normal | **What:** The quality of the encode: lower is better quality and a bigger file (18-23 is the useful range). **Why:** It is the single knob that decides how good the result looks and how big it gets. **When:** 18-20 for the final file, 23-28 for a quick preview. |
| `video.preset` | `str` | normal | **What:** How hard the encoder works: `ultrafast`, `superfast`, `veryfast`, `faster`, `fast`, `medium`, `slow`, `slower`, `veryslow`. **Why:** A slower preset gives a smaller file at the same quality - and takes longer. **When:** `veryslow` gives the best quality per byte for a final render; `veryfast` for a quick look. |
| `video.maxrate_mbps` | `float` | advanced | **What:** A cap on the bitrate in megabits per second; 0 means no cap. **Why:** Keeps the file inside the limits of the platform you upload to. **When:** Leave it at 0 unless the platform has a limit (12 is a common one). |
| `video.audio_bitrate_kbps` | `int` | advanced | **What:** The bitrate of the AAC audio track of every clip. **Why:** More bits keep the music and the room tone; speech is fine at 128-192. **When:** 192 is transparent for speech; raise it to 256 for music-heavy videos. |
| `video.container` | `choice` | advanced | **What:** The file format of the clips: `mp4` (plays everywhere) or `mkv` (holds any codec and audio). **Why:** MKV is more permissive, MP4 is what phones and platforms expect. **When:** Keep `mp4` unless a player refuses the result. Choices: `mp4, mkv`. |
| `video.thumbnail` | `bool` | normal | **What:** Also write a small `.jpg` cover image next to every clip. **Why:** A cover image is what a platform shows before the clip is played. **When:** Keep it on if you upload the clips yourself. |

## Captions

The text burned into the picture, and the hook title

| Path | Kind | Vision | Details |
|---|---|---|---|
| `captions.enabled` | `bool` | normal | **What:** Burn the spoken text into the picture. **Why:** Most people watch a clip without sound, and the captions carry the message. **When:** On for social media and for any clip that has to work muted. |
| `captions.font` | `str` | normal | **What:** The font: `auto` picks a system font that covers the script of your language. **Why:** A font that lacks a glyph shows an empty box instead of the letter. **When:** Leave it at `auto` unless you want a specific typeface (a path to a `.ttf` works too). |
| `captions.size` | `int` | advanced | **What:** The size of the caption text in pixels; empty derives it from the resolution. **Why:** The captions have to be readable on a phone without taking the whole screen. **When:** Empty is fine for any resolution; set it only for a special look. |
| `captions.color` | `str` | normal | **What:** The colour of the caption text. **Why:** It has to contrast with the picture behind it. **When:** White is the safe choice; a brand colour when the series has one. |
| `captions.bg_color` | `str` | normal | **What:** The colour of the box behind the text. **Why:** A box makes the text readable over any picture. **When:** Black with a partly transparent box works on almost everything. |
| `captions.bg_opacity` | `float` | normal | **What:** How transparent the box behind the text is, from 0 (invisible) to 1 (solid). **Why:** A half transparent box keeps the picture visible while the text stays readable. **When:** Around 0.6 is a good compromise; 0 removes the box entirely. |
| `captions.stroke_width` | `int` | advanced | **What:** The width of the outline around the letters. **Why:** An outline keeps the text readable when there is no box behind it. **When:** 1-2 pixels when the background is transparent, otherwise 0. |
| `captions.stroke_color` | `str` | advanced | **What:** The colour of the outline around the letters. **Why:** Usually black, so the text reads on a bright picture. **When:** Only relevant when the outline width is above 0. |
| `captions.highlight` | `bool` | normal | **What:** Colour the word that is being spoken while the rest stays white. **Why:** It guides the eye and makes a clip feel alive - it is the style most short videos use. **When:** On for social media; off for a calmer look or for scripts without spaces. |
| `captions.highlight_color` | `str` | advanced | **What:** The colour of the word that is being spoken. **Why:** A bright colour draws the eye without being loud. **When:** A warm yellow is the common choice. |
| `captions.position` | `choice` | normal | **What:** Where the captions sit in the frame: `top`, `center`, `lower` or `bottom`. **Why:** The bottom is covered by the app bar of most social apps. **When:** `lower` is the safe choice, `top` when the lower part of the picture matters. Choices: `top, center, lower, bottom`. |
| `captions.safe_top` | `float` | advanced | **What:** The share of the frame kept free at the top, as a fraction of its height. **Why:** Keeps the captions clear of the status bar and the channel name. **When:** 0.1 is enough; raise it when something is still in the way. |
| `captions.safe_bottom` | `float` | advanced | **What:** The share of the frame kept free at the bottom, as a fraction of its height. **Why:** Keeps the captions clear of the app bar and the like button. **When:** 0.2 is the usual value for vertical video. |
| `captions.max_chars` | `int` | normal | **What:** How many characters fit on one caption screen before the text is broken up. **Why:** Long lines are hard to read; short ones are easy. **When:** Around 24 characters works for a phone in portrait. |
| `captions.max_seconds` | `float` | normal | **What:** How long one caption screen stays before the next one appears. **Why:** A screen that stays too long has already been read and gets in the way. **When:** Around 2.5 seconds; shorter for a fast speaker. |
| `captions.uppercase` | `bool` | normal | **What:** Write the captions in capital letters. **Why:** Capital letters are easier to read at a glance in short videos. **When:** On for punchy social clips, off for a calmer look. |
| `title.enabled` | `bool` | normal | **What:** Show a short title at the start of the clip. **Why:** The first line tells the viewer what the clip is about, before they decide to stay. **When:** On when the clip is meant to stop the scroll. |
| `title.seconds` | `float` | normal | **What:** How long the title stays on the screen. **Why:** Long enough to read it, short enough not to waste the opening. **When:** Two to three seconds for a short title. |
| `title.position` | `choice` | normal | **What:** Where the title sits: `top`, `center`, `lower` or `bottom`. **Why:** The top is usually free and does not fight with the captions. **When:** `top` for a hook title, `center` for a dramatic intro. Choices: `top, center, lower, bottom`. |

## Audio

The sound of the clips: clean-up, loudness and silence

| Path | Kind | Vision | Details |
|---|---|---|---|
| `audio.enhance` | `bool` | normal | **What:** High-pass the audio, reduce the noise, normalise the loudness of the speech and limit the peaks. **Why:** Clips cut from one video sit at different levels; this makes them sound alike. **When:** On for every clip that is published; off when the sound is already perfect. |
| `audio.denoise` | `choice` | normal | **What:** How the noise is removed: `auto` (spectral gating if the package is there, otherwise ffmpeg), `noisereduce`, `ffmpeg` or `none`. **Why:** The three methods differ in speed and in how much they damage the voice. **When:** `auto` for everything; `none` when the recording is clean. Choices: `auto, noisereduce, ffmpeg, none`. |
| `audio.denoise_strength` | `float` | advanced | **What:** How hard the noise reduction works, from 0 (off) to 1 (aggressive). **Why:** A stronger setting removes more hiss but can sound metallic. **When:** Raise it only while the noise is still audible. |
| `audio.highpass_hz` | `float` | advanced | **What:** Everything below this frequency is removed. **Why:** It removes the rumble of handling noise and the hum of a mains frequency. **When:** 80 Hz is a good default; raise it for a rumbling microphone. |
| `audio.target_dbfs` | `float` | advanced | **What:** The loudness the speech is normalised to, in dBFS (about -14 LUFS is the usual broadcast level). **Why:** Clips that are too quiet are skipped by the viewers. **When:** Leave it at -16; lower it only if the platform complains about the level. |
| `audio.fade_seconds` | `float` | advanced | **What:** The length of the fade in and fade out of the sound. **Why:** A click at the start of a clip is the most common small flaw in an automatic edit. **When:** Around 0.1 seconds; 0 removes the fades. |
| `silence.remove` | `bool` | normal | **What:** Cut the long pauses out of the clip and join the parts that are left. **Why:** Pauses are dead time; removing them makes the clip tighter and faster to watch. **When:** On for every clip; off when the pauses are part of the style. |
| `silence.min_silence` | `float` | normal | **What:** Pauses longer than this many seconds are shortened. **Why:** Short gaps are natural speech, long gaps are waiting, thinking or a break. **When:** Half a second is the usual value; raise it to keep more of the pauses. |
| `silence.keep_padding` | `float` | advanced | **What:** How much of the silence is kept on each side of the cut. **Why:** Without any padding the words run into each other. **When:** Around 0.1 seconds; more when the speaker talks very close together. |
| `silence.threshold_db` | `str` | advanced | **What:** The level below which the audio counts as silence, in dB; `auto` derives it from the recording. **Why:** A fixed threshold fits one recording, the automatic one fits many. **When:** `auto` for mixed material; a number when the level of the recording is known. |
| `silence.remove_fillers` | `bool` | normal | **What:** Remove words like "um", "uh" and "erm" together with the pauses around them. **Why:** Fillers make a clip feel unpolished; they also cost seconds. **When:** On for social clips; off when the speaker's style depends on them. |
| `silence.fillers` | `csv` | advanced | **What:** The words that count as fillers. **Why:** The list only knows English words; your own language needs its own list. **When:** Add the fillers of your language, for example `ähm`, `ehm`. |

## Unsilence

Remove silent spans from the media before processing it

| Path | Kind | Vision | Details |
|---|---|---|---|
| `unsilence.enabled` | `bool` | normal | **What:** Run a pydub/MoviePy pass before transcription or clipping, cutting out silent audio spans and saving unsilence_<video>.mp4. **Why:** A clean source gives tighter candidates and faster processing by avoiding dead air. **When:** Enable it for speech-heavy recordings with long pauses. |
| `unsilence.silence_threshold_db` | `float` | advanced | **What:** Audio below this level is considered silence during pydub detection. **Why:** Too high trims quiet speech, too low leaves silence behind. **When:** Start around -40 and tune so only dead air is removed. |
| `unsilence.min_silence_ms` | `int` | advanced | **What:** Silences at least this long are removed. **Why:** Avoids cutting tiny breaths or brief punctuation pauses. **When:** Use 300-700 ms for normal speech. |
| `unsilence.keep_silence_ms` | `int` | advanced | **What:** Silence retained on each side of a non-silent span. **Why:** Keeps cuts sounding natural and avoids clipping word boundaries. **When:** Leave around 100-200 ms. |
| `unsilence.quality_crf` | `int` | advanced | **What:** 0 gives a visually lossless libx264 intermediate; larger values trade quality for speed. **Why:** This file is only a source for autoclip and will be rendered again. **When:** Use 0 by default and raise it for very fast runs. |
| `unsilence.quality_preset` | `choice` | advanced | **What:** FFmpeg preset for the unsilent video. **Why:** Preset controls speed versus size while quality stays constant. **When:** Use slow normally and medium for large batches. Choices: `medium, slow, slower, veryslow`. |
| `unsilence.audio_bitrate_kbps` | `int` | advanced | **What:** Bitrate of the re-encoded audio. **Why:** Higher values reduce audio loss before transcoding. **When:** Use 320 kbps when speech is already noisy. |
| `unsilence.min_segment_seconds` | `float` | advanced | **What:** Non-silent spans shorter than this are merged or dropped. **Why:** Very short pops should not become separate processing units. **When:** Leave around 0.25 s unless the audio is heavily fragmented. |

## Skip

Steps to leave out of this run

| Path | Kind | Vision | Details |
|---|---|---|---|
| `skip.stt` | `bool` | normal | **What:** Do not run Whisper. An explicit transcript file, a downloaded subtitle and the transcript cache are still used. **Why:** Whisper is the slowest step; a video with subtitles or a cached transcript does not need it again. **When:** On when you know the text comes from elsewhere. Without any text source, highlights fall back to audio-only selection. |
| `skip.denoise` | `bool` | normal | **What:** Do not enhance the audio before Whisper and do not reduce the noise of the clip audio. **Why:** Denoising clean audio can change what the model hears; a studio recording does not need it. **When:** On for clean recordings, or when a transcript came out worse after denoising. |
| `skip.audio_enhance` | `bool` | normal | **What:** Keep the raw audio: no high-pass, no loudness normalisation and no limiter. **Why:** The original mix may be exactly what you want, and normalisation can change the balance. **When:** On for music or carefully mixed material; leave it off for speech recorded on a phone. |
| `skip.audio` | `bool` | normal | **What:** Write the clips without an audio track. **Why:** Some clips are used as silent background, or the sound is added later. **When:** On for B-roll and silent social posts. Pauses cannot be removed without audio, so the clip keeps its full length. |
| `skip.pauses` | `bool` | normal | **What:** Do not shorten long pauses or cut filler words. **Why:** The rhythm of an interview or a comedy bit often depends on the pauses. **When:** On when the cut should keep every breath and every `um`. |
| `skip.caption` | `bool` | normal | **What:** Do not burn captions into the picture. **Why:** A clean picture is sometimes wanted, or the platform adds its own captions. **When:** On when `captions.enabled` is normally on but this run should stay clean. |
| `skip.title` | `bool` | normal | **What:** Do not show the hook title at the start of the clips. **Why:** A title costs the first seconds of a clip; some platforms show the opening frame as the cover. **When:** On when `title.enabled` is normally on but this run needs the picture from the first frame. |
| `skip.fade` | `bool` | normal | **What:** Do not fade the picture or the sound in and out. **Why:** Hard cuts feel snappier, and a fade hides the first frame that a platform may use as a cover. **When:** On for fast-paced edits; off for a softer opening. |
| `skip.thumbnail` | `bool` | normal | **What:** Do not write the `.jpg` next to each clip. **Why:** The image costs a little time, and the platform generates its own cover anyway. **When:** On when only the videos are needed. |
| `skip.llm` | `bool` | normal | **What:** Ignore `llm.enabled` and keep the heuristic ranking for this run. **Why:** The model can be slow or unreachable, and the heuristic order is a good fallback. **When:** On to compare the heuristic choice with the model's, or to keep a run entirely offline. |
| `skip.snap` | `bool` | normal | **What:** Do not move the cut points to the nearest shot change. **Why:** Shot detection costs time and can move a cut away from the spoken word. **When:** On when `clips.snap_to_cuts` is normally on but the cuts already land well. |

## Speed

How much memory and CPU the run may use

| Path | Kind | Vision | Details |
|---|---|---|---|
| `processing.chunk_threshold_minutes` | `float` | advanced | **What:** Videos longer than this many minutes are transcribed in pieces; 0 means always. **Why:** A very long video is never loaded into memory at once, so the run stays stable. **When:** Leave it at 0; only raise it if you transcribe many short videos in a row. |
| `processing.chunk_minutes` | `float` | normal | **What:** The length of one piece of audio given to the transcription model. **Why:** A shorter piece needs less memory, a longer one is transcribed a little faster. **When:** Five minutes is a good balance; raise it on a machine with plenty of memory. |
| `processing.mode` | `choice` | normal | **What:** Whether clips render one after another (`sequential`, the default) or in parallel (`parallel`, adaptive pool). **Why:** Parallel rendering finishes sooner on a multi-core machine; sequential keeps memory use and the log order flat. **When:** Leave it at `sequential` on small machines, use `parallel` when speed matters. Choices: `sequential, parallel`. |
| `resources.cpus` | `int` | normal | **What:** How many processor cores the run may use; 0 means as many as the machine has. **Why:** Fewer cores leave the machine responsive for everything else. **When:** 0 on a dedicated machine; 2-4 on a laptop you are still working on. |
| `resources.max_cpu_percent` | `float` | normal | **What:** The share of the cores the run may take, in percent. **Why:** Keeps the machine usable while the clips are rendered. **When:** Lower it when the fan gets loud, raise it when you want the job done sooner. |
| `resources.max_workers` | `int` | normal | **What:** How many clips are rendered at the same time when parallel; 0 means as many as the memory allows. **Why:** More workers finish sooner but need more memory at the same time. **When:** Leave it at 0; clips already render one at a time by default (sequential mode). |
| `resources.encoding_threads` | `int` | advanced | **What:** CPU threads given to a single render; more can be faster, but multiplies memory per clip. **Why:** Bounds the extract suffix (OOM-safety). **When:** 4 on big machines; 2 on small or when encodes get heavy (libx265). |
| `resources.memory_fraction` | `float` | advanced | **What:** The share of the currently free memory the run may claim. **Why:** The run follows the state of the machine instead of taking a fixed amount. **When:** Lower it (0.5) when other programs need the memory; raise it (0.9) on a free machine. |
| `resources.memory_reserve_mb` | `int` | advanced | **What:** The amount of memory in megabytes that is always left to the operating system. **Why:** The operating system and your other programs need room, even when the run is busy. **When:** 512 MB is enough; raise it to 2048 when the machine swaps. |
| `storage.cache_memory_mb` | `int` | advanced | **What:** How many megabytes of the cache are kept in memory; 0 means as much as is free. **Why:** A memory cache is much faster than one on disk. **When:** Leave it at 0; lower it when the machine runs out of memory. |
| `storage.cache_disk_mb` | `int` | advanced | **What:** The maximum size of the cached data inside the working database, in megabytes. **Why:** A cap keeps the work folder from growing without end. **When:** The default is enough for most projects. |

## LLM & log

The optional re-ranking with a local model, and the log files

| Path | Kind | Vision | Details |
|---|---|---|---|
| `llm.enabled` | `bool` | normal | **What:** Let a local language model look at the candidates and pick the best ones. **Why:** A model understands the meaning of a moment, where the built-in scoring only measures signals. **When:** On when the automatic selection is not good enough and you have a local Ollama or OpenAI-compatible server. |
| `llm.base_url` | `str` | normal | **What:** The address of the model server, for example `http://localhost:11434`. **Why:** The re-ranking sends the candidate texts to this server. **When:** Leave it at the default for Ollama; change it for LM Studio or a server on another machine. |
| `llm.model` | `str` | normal | **What:** The model on the server, for example `llama3.2`. **Why:** A stronger model ranks better but answers slower. **When:** Use the name the server shows for its models. |
| `llm.api_key` | `str` | normal | **What:** The key sent to the server, if it asks for one. **Why:** Some servers (a hosted one, for example) need it. **When:** Only when the server requires a key; it is never written to the log. |
| `llm.top_k` | `int` | advanced | **What:** How many candidates the model is asked to choose from. **Why:** More candidates mean a better choice, but a longer answer from the model. **When:** 12 is enough; raise it to 20 when the selection is still weak. |
| `llm.timeout` | `float` | advanced | **What:** How long the app waits for the model, in seconds. **Why:** A model that never answers must not stop the run. **When:** Raise it for a large model on a slow machine. |
| `logging.enabled` | `bool` | normal | **What:** Write a log file into `<output>/logs/`. **Why:** The log shows every step, the memory use and the reason for a skipped clip. **When:** Keep it on - it is the first place to look when a clip is not what you expected. |
| `logging.level` | `choice` | normal | **What:** How much the log file records: `DEBUG` writes every small step, `INFO` the important ones. **Why:** The detail helps to find out why a moment was not chosen. **When:** `INFO` normally, `DEBUG` when you are chasing a problem. Choices: `DEBUG, INFO, WARNING, ERROR`. |
| `logging.console_level` | `choice` | normal | **What:** How much is printed to the terminal. **Why:** The desktop app shows this output in its log window. **When:** `INFO` to follow the run, `WARNING` for a quiet console. Choices: `DEBUG, INFO, WARNING, ERROR`. |
| `logging.file` | `path` | advanced | **What:** A fixed log file; empty means a new timestamped file in `<output>/logs/`. **Why:** A fixed name is handy when a script collects the logs of many runs. **When:** Empty is fine; set it when the log has to land somewhere specific. |
